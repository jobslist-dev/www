What this assessment evaluates

Questions are drawn across these areas, with one skill per question so a wrong answer tells you something specific rather than just lowering a score.

Backend fundamentals
A calibrated share of data modelling, APIs, and reliability.
Frontend fundamentals
A calibrated share of language behaviour, layout, and state.
The API boundary
The seam where full-stack work is actually judged: contracts, errors, and shared assumptions.
End-to-end debugging
Following a symptom across the boundary instead of stopping at your own layer.
Trade-off judgment
Deciding which side of the stack should absorb a requirement.

What the questions are like

Nearly every question is anchored in supplied code, a described incident, or a concrete situation, so it cannot be answered from the question alone. In practice that means things like:

  • •Trace a request from the interface to storage and back, and name where it fails.
  • •Decide which layer should own validation for a stated requirement.
  • •Read code from either side of the boundary and predict its behaviour.
  • •Choose an error-handling contract two teams can both live with.

We publish the shape of the questions, not the bank itself — real stems, answers and rubrics stay on the server so the assessment keeps working. Questions are about reading and judging code rather than running it.

If you're taking this assessment

You will see the question count, the time limit, the topics and who is asking before you begin. The clock starts when you press start. You can change any answer until you submit, and every answer is saved as you go — a refresh or a dropped connection loses nothing.

What we don't do

  • No webcam. Nothing is filmed.
  • No screen recording and no remote control of the candidate's machine.
  • No browser lockdown, and no penalty for switching tabs.
  • No automatic accusations — a person decides, never a threshold.

What we do instead

  • Every candidate draws a different set of questions from a much larger bank.
  • Timing is held by the server, so the clock cannot be edited in the browser.
  • Invitation links are single-use and expire.
  • Questions are built around supplied code and concrete situations, not recall you can look up.
